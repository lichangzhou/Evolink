EvoLink User Guide

EvoLink does two things, aligning "the titles you want" with "your home media server (Emby / Jellyfin / Plex)":

Version v1.0 Supports Emby / Jellyfin / Plex Supports the 115 cloud drive

What is this

1. Compare missing titles

Compare your "target release list" (from TMDB / third-party JP metadata source / third-party anime metadata source etc.) item by item against "what's already on your media server", to compute what you're missing and what's duplicated. The whole process is read-only against the media server; it never modifies, moves or deletes any file.

2. Cloud drive integration + 302 link swap

Hook cloud-drive media into the media server via strm pointers; at playback EvoLink's proxy signs out a cloud direct link on the fly, the player pulls straight from the cloud CDN, and the media server neither relays nor stores the data.

3. Archive & scrape

Scan cloud directories, identify titles, match TMDB, and generate properly named strm by category - without touching original cloud files.

4. Auto-organize

Weighted dedup (keep only the best of multiple versions), category settings, and delete linkage (deleting a title auto-cleans its strm) keep the media library clean and consistent.

Getting Started

Step 0: one-time setup

  1. Fill in TMDB API Key: Settings -> Basic Settings. Register at themoviedb.org and copy the key under "Settings -> API".The program pre-fills no Key; each person fills in their own. The box shows •••• means it's stored; if you don't want to change it, leave it; the badge on the right Configured / Not filled is easy to spot. Leaving it empty only affects the six release categories (Movies/Shows/Anime/Documentary/Variety/Concert); local library browsing and hidden categories still work.
  2. Fill in HTTP proxy: on the same page. Fill in: same page. Enter the host's LAN IP + port (e.g. 192.168.1.10 / 7890) and click "Test" to verify. The container uses host networking, so entering 127.0.0.1 points to the container itself and always fails. TMDB, Douban, third-party JP metadata source and posters all go through it; Emby and 115 are domestic services and connect directly.
  3. Connect media server: Settings -> Media Server (EMBY Settings). Address is http://IP:8096; the API Key is created in Emby admin under "Settings -> API Keys".Must be generated with an admin account: a normal account can only read libraries it's authorized for, which looks like "only one media library". Up to 3 servers supported.
  4. Pick libraries for each category: lower half of the same page. Click "Select" on the right of each category; multi-select. The numbers shown areindexed item counts, 0 ; 0 means not yet indexed, not that the library is empty. Libraries not assigned to any category join no stats and no comparison.
  5. Log into cloud drives: open "Cloud Drive Login" and log into your 115 account (login state persists in data/, survives restarts).
  6. Configure mounts: make sure those read-only directories are mounted correctly in compose (see "Deployment & Mounts"); this is the prerequisite for 302 link-swap playback.

Step 1: build your target list

You must first tell EvoLink "which titles I want" - these are the "releases / target list". Two sources:

  • Fetch releases: full fetch in reverse-year order x Emby library scope (TMDB / hidden categories via third-party JP metadata source / hidden categories via third-party anime metadata source / charts).
  • Index Emby: brings in theexisting: read in the items already on your media server (read-only).

Step 2: run everything

The "Run Everything" button at bottom-left runs in dependency order: Index Emby -> TMDB releases -> hidden-category IDs -> hidden category -> charts -> compare. First run takes ~10-20 min; six progress bars on the right move in real time (each independent, so you can see where it's stuck). When done, the home page has numbers.

For first use, it's recommended to click "Index Emby" and "Start Compare" separately first, understand the numbers, then use Run Everything to avoid doing too much at once. Incremental fetches never flip "In Library" back to "Missing".

Reading the Numbers

This is the easiest part to misread; explained block by block below.

Decade comparison table: see the gap at a glance

After selecting any category (or subcategory), a table spreads across decades at the top: each row isreleases / local library / gap. E.g. to see 2026 Western movies, click category "Movies" -> subcategory "Western Movies"; the 2026 row shows that year's numbers.Click any rowand the list below shows only that year; click "All" to return to all decades. The three header cells switch along. Hidden categories use the same table (releases from third-party JP metadata source / third-party anime metadata source, local from Emby inventory).

Two rows of numbers on the stats card

Row 1 · Full releases

  • Full releases: how many were released this year in this category on TMDB. Reads only the total, no item downloads, so even old years return instantly.
  • Local Library: your actual item count in Emby for this year.
  • Gap: full releases - local library.

Row 2 · Popular chart

  • Popular chart: actual list count of the top 500 by popularity (up to 500 per year per subcategory).
  • Already owned: of those 500, how many you already have.
  • To fill: of those 500, how many you're missing; click it to list only the missing.

Both rows' "local" is the same number but compares against different things: row 1 against "all market releases", row 2 against "the 500 worth watching". The former shows how big the gap is; the latter decides what to fetch.

View: Releases <-> Local Library

The two "View" chips at the top:Releasesshow the target list,Local Libraryshow actual Emby items. It only decides whatthe list belowlists, not the decade table above (which gives both sets side by side).

Why hidden category has 24999 local but only tens of thousands of releases

Hidden-category releases come from two routes: third-party JP metadata source releases + monthly chart, and its studio-backfilled full history. Combined they still cap out - third-party JP metadata source anonymous access caps at ~3,200 items, and it only covers studios with a page. So "gap K" is alwayswhat's missing from this list, not "you're missing K in the world"; the fuller the list, the closer K is to reality.

Five chips on the status row

  • All: total releases
  • Missing: in releases but not in your Emby
  • In Library: in releases and found in library
  • Possible: title close but ID/ID didn't match, needs manual confirm
  • Uncomparable: too little info (no ID, no ID, no title)

Categories, subcategories & filters

Category: Movies / Shows / Anime / Documentary / Variety / Concert / hidden category.Subcategory: Movies and Shows split into Mandarin / Asian / Western; Anime into Movie / Series; Variety and Concert into Mandarin / Foreign. Clicking a subcategory shows only that subcategory's releases; "Missing K / In Library" are computed per subcategory. Further down are Format / Genre / Region / Series / Library / Chart / Decade, narrowing layer by layer, always within "current category + current view". The number on a subcategory chip is therelease count; hover shows "releases N (missing K) · local inventory M".

Overview · Dashboard

See core numbers at a glance: total releases, gap distribution (missing / in library / possible / uncomparable), background task status, and whether each reverse-proxy service is online.

  • Gap distribution: numbers are on the "releases basis" (your fetched target list), not media-server inventory; see the stats cards below for inventory.
  • Service & reverse-proxy status: see at a glance which 302 reverse-proxy entry (Emby / Jellyfin / Plex) is online and which is down.
  • One-click actions: common actions are gathered here.

Library / Data · Index Libraries / Index Results

  • Media Library: browse the managed media list, filter by category, release status and decade; more filters (charts & release years) under "More Filters".
  • Index Emby (read-only): pull all library items into local SQLite, also recording resolution / bitrate / HDR / size (needed by "One-click dedup"). Full run ~40-90s. A single library failure only skips that library and continues; failures are summarized at the end, so one error no longer zeroes everything. Many libraries showing 0 in the picker just means not yet indexed; run "Index Emby" once.

Analyze · Start Compare

Compare per media server by checking libraries, viewingmissingandduplicatesseparately, with per-library progress. By default only comparesthe checked libraries per category: each hidden category only compares its own category's libraries; unchecked libraries never participate; enable "Cross-library fallback" to scan all Emby libraries.

Four-level matching logic

  • Hidden-category IDs: normalized to "letter-prefix + number" -SSIS-378 / SSIS378 / SSIS-0378 / SSIS-378-C all equivalent; IDs are extracted from av_code, filename and path (Emby metadata sometimes mis-tags, so relying on one source misses some).
  • Hidden-category series names: both sides strip studio brackets,OVA / THE ANIMATION, ＃1 / episode N / vol.3, then judge by exact match > substring > high similarity; having any episode locally counts as having the series.
  • TMDB / IMDb / TVDB ID Exact match; those without ID fall back to "normalized title + year".
  • Possible track: hidden-category IDs that don't match but share studio + near-identical title are marked "possible" (common when local IDs are mis-written by metadata or re-released as collections); not counted as "in library"; hover the card to see the basis.

Cloud · Cloud Drive Login / 302 Assistant

Cloud Drive Login

Log into the 115 cloud drive. After login, scan cloud directories and cross-check three ways against Emby inventory and releases: total cloud videos / also in Emby / cloud-only / not in releases either. Credentials are written only to local data/config.json; click "Log out" to clear immediately; 115 connects directly without a proxy.

Login rate limiting: the cloud side limits login/code frequency. If it says "server temporarily rate-limited",click Send Code only once, wait a few minutes and retry; hammering it only lengthens the window. Login state persists, don't re-login repeatedly.

302 Assistant

Playback pipeline console, with three parts:

  • STRM generation: Add Link, Link Sync, Manual Sync - turn cloud files into strm pointers.
  • 302 link swap: configure each playback target's (Emby / Jellyfin / Plex) 302 reverse-proxy entry port and upstream.
  • 302 logs: the signing/link-swap record of each playback request; look here when debugging.

Archive · Archive & Scrape

Turn "unorganized" cloud directories into a clean library the media server can scan directly: scan directory -> identify title -> match TMDB -> generate properly named .strm.

Safe: archive & scrapenever moves or deletesoriginal cloud files; it only adds strm pointers. To revert, just delete the generated strm.

Archive · Weighted Dedup

The same title often has multiple versions on the cloud drive (4K REMUX / 1080p WEB-DL / Dolby Vision...). Weighted Dedup scores by your region/resolution/source/codec settings and keeps only the best version, so the media library doesn't fill up with duplicates of the same title.

  • Plans are created/imported under "Weighted Dedup"Create & import;
  • Leave empty means "keep all versions of the same title";
  • if unsure, click "Restore default weights" first.

Archive · Category Settings

Define how media is categorized:

  • Category rules: sort titles into folders like "Movies / Shows" by Chinese genre / region names;
  • Keyword replacement: clean up messy release-group naming into tidy titles to improve TMDB match rate.
Category rules directly decide the first-level folder media goes into when archiving (e.g. "Movies", "Shows"); set them before running archive.

Archive · Delete Linkage

When a movie/show is deleted on the media server, EvoLink auto-cleans the corresponding .strm and empty folders, and tells the media server to remove the entry - keeping "cloud pointer" and "media library" always consistent, leaving no dead links.

Delete isn't a hard delete: cleaned strm files first go to the recycle bin (data/strm_trash/) and are recoverable; confirm before emptying.

Cards & Advanced Actions

These features aren't in the left main bar, but in the media library's cards / stats cards / settings pages:

  • Fetch releases (TMDB): full fetch in reverse-year order x Emby library scope, only checked categories and regions; years go from the newest in your library backwards. Each tier is stored immediately, checkpointed per tier, resumes after restart. Only accepts vote_count ≥ 1 items.
  • Fetch hidden-category IDs (third-party JP metadata source): latest releases + monthly chart, only censored (JP). Pages adjustable under Basic Settings "hidden-category fetch pages". TMDB's coverage for this category is extremely low and has no ID field, so it must go through the third-party JP metadata source.
  • Fetch hidden category (third-party anime metadata source): an anime list,key-free, generally needs a proxy in mainland China. Collected by "series"; matching uses title-prefix so it won't cross into other series.
  • Fetch charts: TMDB TOP250, Douban TOP250, trending, now/upcoming, Douban popular, and platform charts for Netflix / Disney+ / HBO Max / Prime Video / Apple TV+ / Hulu.TOP250 is an all-time ranking; each fetch takes the current snapshot's top 250 and auto-drops entries that fall out.
  • Warm posters: bulk pre-fetch posters to disk (hidden category ~160k ~2GB; current category; all ~270k ~25GB). Cached ones are skipped; can be clicked repeatedly and stopped midway.Must run while the proxy is available.
  • Full resume (resumable fetch): fill all three routes up to target quotas without rescanning from scratch each time; completed tiers are skipped; existing library items only have metadata updated.
  • Export list: top-right of the stats card; exports a CSV of the current filter scope (category+subcategory+status+year+genre...). Filter by "Missing" then export for a ready-to-fetch gap list.
  • One-click dedup: scans only the current category's checked Emby libraries for duplicate titles (same tmdb_id / title+year / hidden category by ID).Episodes count by episode: different episodes aren't duplicates; only multiple bitrates of the same episode.Read-only, no delete; you decide which version to keep.
  • Card resource buttons: RE0(film/TV) directly list that title's cloud resources on re0.me (115 / Quark / Ali / Baidu / 123 / Xunlei / magnet), via the fallback channel, by TMDB ID only;Magnet(hidden category) search sukebei + bt4g by ID. Already-owned titles can also be clicked to pick a 4K/high-bitrate version to upgrade.
  • Search: the search box at top,⌘K (Windows Ctrl+K) focuses,Esc clears. Matches Chinese name, original name and hidden-category ID simultaneously; searches as you type, results still constrained by current category and view.

Core Concepts

strm file

A tiny text file of just a few bytes containing one line: the cloud file's path or pickcode. The media server scans it into the library as "one movie". At real playback, EvoLink's proxy reads that line to sign out a direct link.

302 link swap

A playback request first hits EvoLink's reverse-proxy entry; the proxy parses the strm -> requests and signs with the cloud -> returns 302 a redirect pointing the player to the cloud CDN direct link. So the media serverrelays no traffic, CPU/bandwidth load is near zero; the player connects straight to the cloud CDN at the same speed as the cloud client; Emby / Jellyfin / Plex each have their own 302 entry.

Local mount mode

EvoLink follows the path prefix written in the strm to the local CD2 (CloudDrive2) mount point to find the real file -it doesn't scan the whole cloud drive. So as long as the directory CD2 exposes on the NAS is mounted into the container /CloudNAS, the path prefix in the strm can be correctly recognized and stripped.

Direct link

The final cloud CDN link the 302 points to, with a time-limited signature; the player can stream from it directly.

WAL trap: the media server database uses WAL mode; when mounting youmust mount the whole data directory, not just the main .db file, otherwise un-checkpointed transactions are missed and items are mis-judged as "missing from library".
CD2 propagation: CD2 uses shared to propagate sub-mounts (CloudDrive) outward; consumers (Emby/Jellyfin/Plex) must also mount thesamehost path into their own /CloudNAS and use rshared to receive it, so all three ends' strm path prefixes match.
host networking: EvoLink uses host networking, so there is no ports section - services bind directly to host ports (9191 for the admin UI; playback reverse-proxy entries are under "302 Assistant"). Change ports in the web UI, don't add ports in compose.

FAQ

Many libraries show 0 in the picker

Not yet indexed. Run "Index Emby" once.0 is the "indexed item count", not live Emby inventory.

Can only see one media library

The API Key wasn't generated with an admin account. Go to Emby and create a new Key with an admin account.

Fetching releases returns 401 / says not filled in

Fill in your own TMDB API Key under "Basic Settings". The program pre-fills no Key and shares none.

All network requests time out

The proxy is off, or you entered 127.0.0.1(the container's internal address). Change to the host's LAN IP and click "Test" to confirm.

The gap number is absurdly large

Check the "Data Update" page progress first: fetching is inreverse-year order, so 2026 must finish before 2025; years not yet reached show 0 releases. If a fetched year still looks large, that's normal - TMDB's basis includes shorts, TV movies and co-production double-counting; already vote_count ≥ 1 filtered, but not identical to "worth-collecting feature films".

Numbers don't match the TMDB site

Normal. TMDB's total_results varies with filter parameters and the site has no "X Mandarin movies total" page; region / Mandarin basis are aggregated by this program; the list API hard-caps at 500 pages / 10,000 items, so a single year+region over 10k gets truncated (the log notes it). To verify strictly, pick a narrow condition (e.g. "2023 / China / Drama") and compare against TMDB's returned total.

Clicking play does nothing / keeps spinning

  • First check the "302 logs" for signing errors;
  • confirm all three read-only mounts (strm library, CD2 (/CloudNAS), media server database) are present in compose;
  • confirm the media server side treats EvoLink's 302 reverse-proxy entry as an "external/direct" address (don't let it go through a proxy again).

Comparison numbers don't match my library

Most likely the media server database mounted only the main file, not the whole data directory (WAL trap), or "Index Emby" hasn't been run in a while. Remount the whole data directory and re-index once.

Config/tasks lost after container restart

Notes /app/data Not mounted. Check the host path of the data mount in compose and confirm config.json is ls /app/data visible inside the container.

Cloud login keeps getting rate-limited

Don't hammer Send Code; when you see a rate-limit notice, stop and wait a few minutes. Login state persists; log in once and it lasts.

Settings revert after restart

Fixed (atomic writes + rolling backups + self-healing on corruption). If still abnormal, first check whether the value in data/config.bak.1.json is complete.

Mobile browser buttons blank / numbers overlap

Fixed; refresh the page. If still old style, the browser cache hasn't updated; force-refresh or use a private window.

RE0 can't find sources

Use the "Test direct" in settings to pinpoint by stage: proxy exit / Cloudflare / login state / real lookup. All four green means the chain is fine, and RE0 simply doesn't have that title (common for obscure, new, or domestic shows).
