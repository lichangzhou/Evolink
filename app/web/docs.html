EvoLink 使用文档

EvoLink 做两件事，帮你把「想看的片」和「家里媒体服务器（Emby / Jellyfin / Plex）」对齐：

版本 v1.0 支持 Emby / Jellyfin / Plex 支持 115 网盘

这是什么

① 比对缺片

把你的「目标发行片清单」（来自 TMDB / 第三方日系元数据源 / 第三方动漫元数据源 等）和「媒体服务器里已有的」逐条比对，算出你缺哪些、重复哪些。全程只读媒体服务器，不修改、移动或删除任何文件。

② 网盘接库 + 302 换链

把网盘里的影视用 strm 指针接进媒体服务器，点播放时由 EvoLink 反代即时签出网盘直链，播放器直接拉网盘 CDN，媒体服务器不中转、不占存储。

③ 归档刮削

扫描网盘目录，识别片名、匹配 TMDB、按分类生成规范命名的 strm，不碰网盘原文件。

④ 自动整理

权重洗板（同片多版本只留最优）、分类设置、删除联动（删片自动清 strm），让媒体库始终干净一致。

新手上路

第 0 步：前置准备（只做一次）

  1. 填 TMDB API Key：设置 → 基础设置。到 themoviedb.org 注册，在「设置 → API」复制密钥。程序不预置任何 Key，每人填自己的。框里显示 •••• 表示已存有，不想换就别动；右侧徽标 已配置 / 未填写 一眼可辨。不填只影响电影/剧集/动画/纪录片/综艺/演唱会六类发行片，本地库浏览、隐藏分类照常可用。
  2. 填 HTTP 代理：同一页。填宿主机的局域网 IP + 端口（如 192.168.1.10 / 7890），点「测试」验证。容器是 host 网络，填 127.0.0.1 会指向容器自己，必然失败。TMDB、豆瓣、第三方日系元数据源、海报都走它；Emby 和 115 是境内服务，直连不走代理。
  3. 连接媒体服务器：设置 → 媒体服务器（EMBY 设置）。地址填 http://IP:8096，API Key 在 Emby 后台「设置 → API 密钥」新建。必须用管理员账号生成：普通账号只能读到自己被授权的库，会表现为「只看到一个媒体库」。最多支持 3 台。
  4. 给每个分类选库：同一页下半部分。每个分类点右侧「选库」，可多选。这里显示的数字是已索引条目数，0 表示还没索引过，不代表库里没片。没归到任何分类的库不参与统计也不参与比对。
  5. 登录网盘：进入「网盘登录」，登录你的 115 账号（登录态持久化在 data/，重启不丢）。
  6. 配置挂载：确保 compose 里那几个只读目录挂对了（详见「部署与挂载」），这是 302 换链能否播放的前提。

第 1 步：建立目标清单

你总得先告诉 EvoLink「我想看哪些片」——这些就是「发行片 / 目标清单」。两种来源：

  • 拉取发行片：按年份倒序 × Emby 库范围全量抓（TMDB / 隐藏分类 走 第三方日系元数据源 / 隐藏分类走 第三方动漫元数据源 / 榜单）。
  • 索引 Emby：把媒体服务器里已有的条目读进来（只读）。

第 2 步：一键跑全套

左下角「一键跑全套」按依赖顺序跑：索引 Emby → TMDB 发行片 → 隐藏分类 番号 → 隐藏分类 → 榜单 → 比对。首次约 10–20 分钟，右侧六条进度条实时走（每条独立，可看清卡在哪一步）。跑完首页就有数字了。

首次用建议先单独点「索引 Emby」和「开始比对」，看明白数字含义后再用一键全套，避免一次动太多心里没底。增量拉取不会把「已在库」打回「缺少」。

数字怎么看

这是最容易看懵的地方，逐块说明。

年代对比表：一眼看清差多少

选中任意分类（或子类）后，顶部会出一张按年代铺开的表：每行是发行片 / 本地库 / 缺口。例：想看 2026 年欧美电影，先点分类「电影」→ 子类「欧美电影」，表里 2026 那一行就是这一年的数字。点任意一行，下面的列表立刻只显示那一年；再点「全部」回到全部年代。表头三格跟着切换。隐藏分类用的是同一张表（发行片来自 第三方日系元数据源 / 第三方动漫元数据源，本地库来自 Emby 库存）。

统计卡上的两排数字

第一排 · 全量发行

  • 全量发行：这一年这一类在 TMDB 上一共发行了多少部。只读总数，不下载条目，所以再老的年份也能立刻给出。
  • 本地库：你 Emby 里这一年的实际条目数。
  • 缺口：全量发行 − 本地库。

第二排 · 热门榜

  • 热门榜：热度前 500 条的实际清单条数（每年每子类最多 500）。
  • 榜内已有：这 500 条里你库里已经有的。
  • 待补：这 500 条里你还缺的，点它可以只列缺的。

两排的「本地」是同一个数，但对比对象不同：第一排对比「市场上全部发行」，第二排对比「值得看的 500 部」。前者看差距多大，后者决定下什么。

视角：发行片 ↔ 本地库

顶部「视角」两个 chip：发行片看目标清单，本地库看 Emby 实际条目。它只决定下面的列表列什么，不影响上面的年代对比表（表里两套数字并排给）。

为什么 隐藏分类 本地 24999、发行片只有几万

隐藏分类 发行片来自两路：第三方日系元数据源 的发行 + 月榜，以及 第三方日系元数据源 按片商回灌的全史。两路合并后仍有上限——第三方日系元数据源 匿名约 3,200 条封顶，第三方日系元数据源 只覆盖有片商页面的厂牌。所以「缺口 K」永远是这份清单里你没有的，不是「全世界你缺 K 部」；清单越全，K 越接近真实。

状态行五个 chip

  • 全部：发行片总条数
  • 缺少：发行片里有、你 Emby 里没有
  • 已在库：发行片里有、库里也找到了
  • 疑似有：标题相近但 ID / 番号没对上，需要人工确认
  • 无法比对：条目信息太少（无 ID、无番号、无片名）

分类、子类与筛选

分类：电影 / 剧集 / 动画 / 纪录片 / 综艺 / 演唱会 / 隐藏分类。子类：电影、剧集分国语 / 亚洲 / 欧美；动画分电影 / 剧集；综艺、演唱会分国语 / 外语。点子类只看该类发行片，「缺 K / 已在库」都按子类算。再往下还有片型 / 类型 / 地区 / 系列 / 库 / 榜单 / 年代，逐层收窄，范围始终在「当前分类 + 当前视角」内。子类 chip 上的数字是发行片条数，鼠标悬停会显示「发行片 N（缺 K）· 本地库存 M」。

栏目总览

左侧栏按功能分组，下面逐栏说明「干什么、怎么用、常见坑」。

总览 · 仪表盘

一屏看完核心数字：发行片总量、缺口分布（缺 / 已在库 / 疑似 / 无法比对）、后台任务状态、各反代服务是否在线。

  • 缺口分布：数字都是「发行片口径」（你拉来的目标清单），不是媒体服务器库存；库存数字看下方统计卡。
  • 服务与反代状态：一目了然哪个 302 反代入口（Emby / Jellyfin / Plex）在线、哪个挂了。
  • 一键操作：常用动作集中在这里。

媒体库 / 数据 · 索引媒体库 / 索引结果

  • 媒体库：浏览已纳入管理的媒体清单，按分类、发行片状态、年代筛选；「更多筛选」里还有榜单与发行年代。
  • 索引 Emby（只读）：拉全库条目进本地 SQLite，顺带记录分辨率 / 码率 / HDR / 体积（「一键排重」要用）。全量约 40–90 秒。单个库失败只跳过该库、其余继续，结束时汇总失败清单，不会再「一个库报错全盘归零」。选库抽屉里很多库显示 0 就是还没索引，跑一次「索引 Emby」即可。

分析 · 开始比对

按媒体服务器逐库勾选进行比对，分别看缺失与重复，每个库单独显示进度。默认只比各分类勾选的库：各个隐藏分类只比自己分类下的库，没勾的库一律不参与；开启「跨库兜底」才扫描全部 Emby 库。

四级匹配逻辑

  • 隐藏分类 番号：统一成「字母前缀＋数字」——SSIS-378 / SSIS378 / SSIS-0378 / SSIS-378-C 全部等价；番号同时从 av_code、文件名、路径三处提取（Emby 元数据偶尔会把番号挂错，只认一处必漏）。
  • 隐藏分类系列名：两边都去掉制作组方括号、OVA / THE ANIMATION、＃1 / 第N幕 / vol.3，再按 完全相同 › 互为子串 › 高度相似 判；本地是某一集也算有这个系列。
  • TMDB / IMDb / TVDB ID 精确匹配；没有 ID 的退回「归一化标题 + 年份」。
  • 疑似轨：隐藏分类 番号对不上、但同厂牌 + 标题几乎一字不差时标「疑似」（常见于本地番号被元数据写错或合集重发），不算「已在库」，卡片上悬停能看到依据。

网盘 · 网盘登录 / 302 助手

网盘登录

登录 115 网盘。登录后扫描网盘目录，跟 Emby 库存、发行片三方交叉：网盘视频总数 / Emby 也有 / 仅在网盘 / 发行片也没有。凭证只写在本地 data/config.json，点「退出」立即清空；115 直连不走代理。

登录限流：网盘侧对登录/发码有频率限制。如果提示「服务器暂时限流」，只点一次发送验证码，隔几分钟再试；连续狂点只会拉长限制窗口。登录态持久化，别反复重登。

302 助手

播放链路总控台，含三块：

  • STRM 生成：添加链接、链接同步、手动同步——把网盘文件生成 strm 指针。
  • 302 换链：配置各播放端（Emby / Jellyfin / Plex）的 302 反代入口端口与上游。
  • 302 日志：每次播放请求的签名/换链记录，排错时看这里。

归档 · 归档刮削

把网盘里「还没整理」的目录，自动变成「媒体服务器能直接扫」的规范库：扫描目录 → 识别片名 → 匹配 TMDB → 按分类生成规范命名的 .strm。

安全：归档刮削不移动、不删除网盘原文件，只新增 strm 指针。要回退，删掉生成的 strm 即可。

归档 · 权重洗板

同一部片子网盘里常有多个版本（4K REMUX / 1080p WEB-DL / 杜比视界…）。权重洗板按你设的地区/分辨率/片源/编码等属性打分，只保留最优版本，避免媒体库里同一片刷出一堆。

  • 方案在「权重洗板」里新建和导入；
  • 留空表示「同一作品的所有版本都保留」；
  • 不确定就先点「恢复默认配比」。

归档 · 分类设置

定义媒体怎么归类：

  • 分类规则：按中文类型名 / 中文地区名把片子分到「电影 / 剧集」等目录；
  • 识别词替换：把乱七八糟的发布组命名规整成干净片名，提升 TMDB 匹配率。
分类规则直接决定归档时媒体放进哪个第一层目录（如「电影」「剧集」），建议先定好再跑归档。

归档 · 删除联动

在媒体服务器里删除一部电影/剧集时，EvoLink 自动清理对应的 .strm 与空目录，并通知媒体服务器移除条目——保持「网盘指针」和「媒体库」始终一致，不残留死链。

删除不是硬删：被清的 strm 会先移入回收站（data/strm_trash/）可恢复，确认无误后再清空。

卡片与高级操作

这些功能不在左侧主栏，而在媒体库的卡片 / 统计卡 / 设置页里：

  • 拉取发行片（TMDB）：按年份倒序 × Emby 库范围全量抓，只抓勾选的分类和地区；年份从库里最新一年往回走。每抓完一档立即入库，断点按档记，重启后接着跑。只收 vote_count ≥ 1 的条目。
  • 拉取 隐藏分类 番号（第三方日系元数据源）：最新发行 + 月榜，只抓有码（日系）。页数在基础设置「隐藏分类 抓取页数」调。TMDB 上的 隐藏分类 覆盖率极低且没有番号字段，所以 隐藏分类 必须走 第三方日系元数据源。
  • 拉取隐藏分类（第三方动漫元数据源）：动漫动画清单，免 Key，国内一般需代理。按「系列」收录，比对按标题前缀判定，不会串到别的系列。
  • 拉取榜单：TMDB TOP250、豆瓣 TOP250、趋势、正在/即将上映、豆瓣热门，以及 Netflix / Disney+ / HBO Max / Prime Video / Apple TV+ / Hulu 平台榜。TOP250 是全时段排名，每次拉取取当前快照前 250，跌出的旧条目会自动摘掉。
  • 预热封面：把封面提前批量抓下来落盘（仅 隐藏分类 ≈16 万张≈2GB；当前分类；全部 ≈27 万张≈25GB）。已有缓存自动跳过，可反复点、可中途停。必须代理可用时跑。
  • 全量续抓（断点续抓）：把三路往目标配额拉满，不会每次从头扫，已抓完的档直接跳过；库里已有条目只更新元数据。
  • 导出清单：统计卡右上角，导出当前筛选范围（分类+子类+状态+年份+类型…）的 CSV，按「缺少」筛完导出就是一份可直接下片的缺口清单。
  • 一键排重：只扫当前分类勾选的 Emby 库，找同片多文件（同 tmdb_id / 标题+年份 / 隐藏分类按番号）。剧集按集数算：不同集不算重复，同一集高低码多份才算。只读不删，洗哪个版你自己定。
  • 卡片资源按钮：RE0（影视）直接列出该片在 re0.me 的网盘资源（115 / 夸克 / 阿里 / 百度 / 123 / 迅雷 / 磁力），走兜底通道，只认 TMDB ID；磁力（隐藏分类）按番号直查 sukebei + bt4g。已入库的片也能点，用来挑 4K / 高码率版本洗版。
  • 搜索：顶部搜索框，⌘K（Windows Ctrl+K）聚焦、Esc 清空。同时匹配中文名、原名、隐藏分类 番号，输入即搜，结果仍受当前分类与视角约束。

核心概念

strm 文件

一个只有几字节的文本文件，里面就一行：网盘文件的路径或 pickcode。媒体服务器把它扫进库当成「一部影片」。真正播放时，EvoLink 反代读取这一行去签出直链。

302 换链

播放请求先到 EvoLink 的反代入口，反代解析 strm → 向网盘请求并签名 → 返回 302 重定向把播放器指到网盘 CDN 直链。于是媒体服务器不中转流量，CPU/带宽几乎零负担；播放器直连网盘 CDN，速度和直接用网盘客户端一致；支持 Emby / Jellyfin / Plex 三端各自的 302 入口。

本地挂载模式

EvoLink 顺着 strm 里写的路径前缀，到本地 CD2（CloudDrive2）挂载点找真实文件——不扫描整个网盘。所以只要把 CD2 在 NAS 上暴露的目录挂进容器 /CloudNAS，strm 里的路径前缀就能被正确识别和剥离。

直链

最终 302 指向的那个网盘 CDN 链接，带有时效签名，播放器拿到即可直接拉流。

部署与挂载

容器内部目标路径是固定的，你需要改的只有左边（宿主）路径，按自己的 NAS 填。下面给出多系统示例，没有硬性要求、按习惯来。

容器内（固定，勿改）用途宿主左侧示例

WAL 陷阱：媒体服务器数据库是 WAL 模式，挂载时必须挂整个 data 目录，不能只挂主 .db 文件，否则读不到未 checkpoint 的事务，会误判「库中缺失」。
CD2 传播：CD2 用 shared 把子挂载（CloudDrive）往外传播；消费方（Emby/Jellyfin/Plex）也要把同一个宿主路径挂到各自的 /CloudNAS 并用 rshared 接收，这样三端 strm 路径前缀一致。
host 网络：EvoLink 用 host 网络，所以没有 ports 段——服务直接绑宿主机端口（9191 管理界面，播放端反代入口见「302 助手」）。改端口去网页里改，别在 compose 里加 ports。

常见问题

选库抽屉里很多库显示 0

还没索引。跑一次「索引 Emby」即可。0 是「已索引条数」，不是 Emby 实时库存。

只能看到一个媒体库

API Key 不是管理员账号生成的。去 Emby 用管理员账号重新建一个 Key。

拉发行片报 401 / 提示未填写

去「基础设置」填自己的 TMDB API Key。程序不预置 Key，也不共用别人的。

所有网络请求超时

代理没开，或填成了 127.0.0.1（容器内部地址）。改成宿主机局域网 IP，点「测试」确认。

缺口数字大得离谱

先看「数据更新」页进度：抓取是年份倒序，2026 抓完才轮到 2025，没轮到的年份发行片是 0。若该年已抓过还觉得大属正常——TMDB 口径包含短片、电视电影、合拍片重复归属；已用 vote_count ≥ 1 过滤，但不能完全等同「值得收藏的长片」。

和 TMDB 官网数字对不上

正常。TMDB 的 total_results 随筛选参数变化，官网没有「国语电影共 X 部」这种页面；地区 / 国语口径是本程序自己聚合的；列表接口硬上限 500 页 / 1 万条，单年单地区超 1 万条的会被截断（日志会提示）。要严密验证，挑一个窄条件（如「2023 / 中国 / 剧情片」）跟 TMDB 返回总数对拍。

点播放没反应 / 一直转圈

  • 先看「302 日志」有没有签名报错；
  • 确认 compose 里 strm 库、CD2（/CloudNAS）、媒体服务器数据库三个只读挂载都在；
  • 确认媒体服务器侧把 EvoLink 的 302 反代入口当成「外网/直连」地址（别让它再走一遍反代）。

比对数字和我库里对不上

多半是媒体服务器数据库只挂了主文件没挂整个 data 目录（WAL 陷阱），或索引 Emby 太久没更新。重挂整个 data 目录、重新索引一次即可。

容器重启后配置/任务丢了

说明 /app/data 没挂上。检查 compose 里 data 挂载的宿主路径，确认容器内能 ls /app/data 看到 config.json。

网盘登录总被限流

别连续点发送验证码；收到限流提示就停手等几分钟。登录态持久化，一次登好长期有效。

设置改完重启就没了

已修（原子写 + 滚动备份 + 损坏自愈）。若仍异常，先看 data/config.bak.1.json 里的值是否完整。

手机浏览器按钮空白 / 数字重叠

已修，刷新页面即可。仍是旧样式说明浏览器缓存没更新，强制刷新或换无痕窗口。

RE0 查不到片源

先用设置里的「测试直连」分段定位：代理出口 / Cloudflare / 登录态 / 实查。四段全绿说明链路正常，那就是 RE0 本身没有这部片（冷门、新片、国产剧常见）。
